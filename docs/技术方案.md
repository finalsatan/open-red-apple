# win-red-apple 技术方案

基于 [openhongguo](https://github.com/beilunyang/openhongguo) SDK 开发 Windows 11 桌面端短剧应用。

> 本文档只做技术设计，不含实现。所有内容以学习研究为目的，禁止商用。

## 1. 目标与范围

一个 Windows 11 原生桌面短剧客户端，能力对齐红果 App 的主要浏览与播放路径，并支持**手柄全流程操作**：

- 发现（书城频道：推荐、电影、漫剧等）
- 搜索（联想词、热搜、提示词、类型筛选）
- 短剧详情（元数据、分集、多季、相关推荐、演员）
- 播放（清晰度切换、进度记忆、自动下一集、竖屏/横屏）
- 榜单（短剧榜、演员榜）与分类筛选
- 演员主页
- **手柄操作（浏览 / 播放 / 搜索，适配 10-foot 电视与掌机场景）**
- 观看记录 / 收藏
- 设置（设备管理、缓存、接口地址、手柄映射）

不在第一版范围：登录/付费内容、下载离线、评论、投屏。

## 2. 技术选型

### 2.1 候选方案对比

| 方案 | 后端语言 | 用 SDK 的方式 | 视频播放 | 体积/打包 | 结论 |
|---|---|---|---|---|---|
| **Wails v2** | Go | 直接 `import` Go SDK | WebView2 + hls.js，本地 ffmpeg 解密 | 单 exe + WebView2，小 | **推荐** |
| Flutter Windows | Dart | 需自写 Windows FFI 插件加载 Go c-shared DLL | video_player 桌面支持弱 | 中 | 工作量大 |
| Electron | Node | `openhongguo` npm（WASM） | Chromium 原生强 | 150MB+，双运行时 | 可用但重 |
| Tauri | Rust | 需 sidecar 或 FFI 调 Go | WebView2 | 小 | 跨语言桥接复杂 |

### 2.2 结论：Wails v2

理由：

1. **零胶水**：openhongguo 的 `sdk` 和 `adapters` 是纯 Go，Wails 后端直接 `go get github.com/beilunyang/openhongguo`，类型和错误哨兵都能原样用。
2. **WebView2**：Windows 11 预装，`<video>` + MSE 能力足够；HLS 用 `hls.js`，加密流由后端解密后转本地 HLS。
3. **可交叉编译**：Linux 上 `wails build -platform windows/amd64` 产出 `.exe`，可再用 NSIS 出安装包。
4. **单进程**：Go 后端可同时跑本地媒体网关、SQLite、SDK 客户端和手柄输入轮询，生命周期简单。

前端建议：**React + TypeScript + Vite + Tailwind CSS + hls.js + Zustand + `@noriginmedia/norigin-spatial-navigation`**（焦点导航）。

## 4. 关键难点与方案

### 4.1 加密分集播放（cenc-aes-ctr）

openhongguo 返回的 `Playback.Streams[].Protected` 为 true 时是 `cenc-aes-ctr` 加密，WebView2 的 `<video>` **无法**直接播放（这不是标准 ClearKey EME，是自定义方案）。参考仓库的做法是：把内容密钥 `key.Hex` 交给 ffmpeg 的 `-decryption_key`。

方案：**本地 ffmpeg 解密 + 转本地 HLS**。

```
ffmpeg -decryption_key <hex> -i <上游URL> \
  -c copy -f hls -hls_time 6 -hls_playlist_type event \
  -hls_segment_type mpegts -hls_flags independent_segments \
  <cacheDir>/index.m3u8
```

- Go 网关把 `index.m3u8` 和 `.ts` 分片通过 `127.0.0.1` 暴露给 hls.js。
- `-hls_playlist_type event` 让播放列表随 ffmpeg 写入增长，实现"边下边播"。
- 拖动进度：hls.js 直接请求已有分片；未生成的位置由前端提示缓冲。
- 清晰度切换：换用对应 `Stream.URL` 重启一条 ffmpeg 管线（每档一个 token）。
- 全部走本地网关还能顺带解决 CDN 的 CORS / Range / 请求头问题。

ffmpeg 处理：
- 首次启动下载到 `%LOCALAPPDATA%\win-red-apple\bin\ffmpeg.exe`（校验 SHA256），或随安装包内置精简版。
- 找不到 ffmpeg 时，加密分集给出明确提示，清晰分集仍可播。

### 4.2 匿名设备"一次播放"限流

SDK 文档明确：自 2026-10-29 起，服务端基本只给每台匿名设备返回一次播放模型，之后 `ResolvePlayback` 返回空 → `ErrAnonymousLimited`。CLI 的做法是 `ResetDevice` 后重试。

封装层实现（照搬 CLI 的 `resolvePlayback`，但要并发安全）：

```
resolvePlayback(episodeId):
  for i in 0..2:
    pb = client.ResolvePlayback(episodeId)
    if pb != nil: return pb
    if !errors.Is(err, ErrAnonymousLimited): return err
    mutex.lock(); client.ResetDevice(); mutex.unlock()
  return err
```

要点：
- 读取类接口（发现/搜索/详情等）不受限流影响，用**一个主 `Client`**（`filestore` 持久化设备档案）。
- 播放解析单独用**设备池**：N 个独立 `Client`，各自一个 `memstore`（懒注册），互不干扰。
- 池的取用与刷新：

```
Acquire() -> *Client              // 取一个"未消耗"设备；池空则新建或等待
ResolvePlayback(id):
  for attempt in 0..(poolSize + 2):
    c = pool.Acquire()
    pb, err = c.ResolvePlayback(id)
    if pb != nil: pool.Release(c, consumed=true); return pb   // 消耗掉，后台补新设备
    if !errors.Is(err, ErrAnonymousLimited): pool.Release(c, consumed=false); return err
    pool.Release(c, consumed=true)                            // 空结果也算消耗，换下一个
  return ErrAnonymousLimited
```

- `Release(c, consumed=true)` 时后台对 c 调 `ResetDevice` 重新注册设备再放回池中，保证池里始终有可用设备。
- 播放前**预取下一集**：从池中预留一个设备解析下一集模型，切集时零等待。
- 默认池大小 5，可配置；注册新设备有网络成本，需要限速与退避。
- 风险：新设备首请求也不一定成功，且服务端可能进一步收紧。保留自动重置+退避作为兜底，并做失败熔断（连续失败则暂停播放并提示）。

### 4.3 媒体格式分支

按 `Playback` 字段决定管线：

| 情况 | 处理 |
|---|---|
| 清晰 + 单文件 MP4 | 本地网关反代，透传 `Range`，`<video src>` 直接播 |
| 清晰 + HLS (`hls=true`) | 网关拉 m3u8，重写分片地址到网关，hls.js 播放 |
| 清晰 + DASH (`dash=true`) | 用 ffmpeg 把 video+`audio_url` 合流转 HLS |
| 加密（任意） | ffmpeg `-decryption_key` 转本地 HLS |
| 主 CDN 失败 | 自动切 `Stream.BackupURL` 重试一次 |

## 5. 手柄操作设计

手柄不是"再加一个输入源"，而是一条贯穿全局的交互约束：**所有可点的地方都必须可聚焦、可 D-pad 到达、有明确焦点态**。目标是键鼠和手柄都能完整使用。

### 5.1 目标体验

- 全流程纯手柄可操作：浏览 → 详情 → 播放 → 切集 → 搜索。
- 适配 10-foot 电视场景和 Windows 掌机（ROG Ally、Steam Deck Win 等）。
- 插上即用，连接/断开有提示；键鼠操作时隐藏手柄焦点环，手柄一动焦点环出现。
- 大焦点、清晰高亮、底部按键提示。

### 5.2 输入采集：两条路线

| 路线 | 实现 | 优点 | 缺点 |
|---|---|---|---|
| **主：原生 Go + XInput** | `syscall.NewLazyDLL("xinput1_4.dll")`，60Hz 轮询，状态变化才通过 Wails 事件推送 | 纯 Go 无 CGO，可交叉编译；不依赖窗口焦点；可靠 | 只覆盖 Xbox 系 / XInput 兼容手柄 |
| **备：WebView2 Gamepad API** | 前端 `navigator.getGamepads()` + rAF 轮询 | 零原生代码，Chromium 能识别的都能用 | 需窗口聚焦，部分手柄识别不稳定 |

建议**以原生 XInput 为主**（可靠、跨焦点），HTML5 Gamepad API 作为兜底。两者都归一化为同一套**动作事件**，前端只认动作，不认具体手柄。

- 原生代码用 `//go:build windows` 保护，其他平台提供空实现 stub，方便在 Linux 上做前端迭代。
- PS / Switch 手柄建议经 **Steam Input / DS4Windows** 映射为 XInput（在设置页给出说明）。
- 后续可扩展 DirectInput / RawInput 支持非 XInput 手柄。

### 5.3 动作抽象层

后端（或前端）把按键/摇杆归一为动作，前端各页面只消费动作：

```
up / down / left / right
confirm / back / menu / search / favorite
playPause / seekBackward / seekForward
previousEpisode / nextEpisode
```

好处：改键位、换手柄、加键盘映射都只改映射表，不动页面逻辑。

### 5.4 默认映射（可在设置页修改）

| 动作 | 手柄 | 键盘 |
|---|---|---|
| 上 / 下 / 左 / 右 | 左摇杆 / 十字键 | 方向键 |
| 确认 | A | Enter |
| 返回 | B | Esc |
| 收藏 | X | F |
| 搜索 | Y | / |
| 播放 / 暂停 | A | Space |
| 快退 / 快进 | 左 / 右摇杆（按住可变速率） | ← / → |
| 上一集 / 下一集 | LB / RB | P / N |
| 菜单（清晰度、选集） | Start / Menu | M |
| 退出播放器 / 返回首页 | View / Back | Home |

### 5.5 焦点与空间导航

- 使用 `@noriginmedia/norigin-spatial-navigation`：给卡片、按钮、分集、筛选项加 `focusable`。
- 焦点环样式统一；焦点进入视口时自动滚动（`scrollIntoView({ block: "nearest" })`）。
- 每个页面进入时设置默认焦点；返回时恢复到来源元素。
- 弹层 / 播放器用 **focus trap**，防止焦点跑到底层页面。
- 鼠标 hover 与手柄焦点互斥：记录"当前输入方式"，只显示对应的高亮。

### 5.6 播放器手柄控制

- A 播放/暂停，B 退出，LB/RB 切集，Start 打开清晰度/选集菜单，Y 收藏。
- 左/右摇杆按住快进/快退，松开回到原速率；死区（deadzone）与方向重复率单独处理，避免误触。
- 进度条显示当前缓冲和已解密分片范围；缓冲时给出转圈提示。

### 5.7 搜索的手柄输入

手柄打字是主要痛点，分三层解决：

1. 搜索页默认展示**热搜 / 历史 / 联想词**，D-pad 直接选，A 即搜（覆盖大多数场景）。
2. 提供 **D-pad 可导航的屏幕键盘（OSK）**；中文支持拼音首字母候选。
3. 可选：调起 Windows 触摸键盘（`TabTip.exe`）配合实体键盘。

### 5.8 反馈、状态与提示

- 不做震动反馈（已确认）。
- 连接 / 断开 toast，并自动切换当前输入方式。
- 底部按键提示条：显示当前上下文可用动作，3 秒无操作淡出，任意按键唤出。

## 6. 后端设计

### 6.1 SDK 封装 `internal/ohg`

- `NewClient()`：`adapters.NewClient(profilePath, sdk.Options{RetryAttempts: 3, Logger: ...})`。
- 设备档案路径：`%APPDATA%\win-red-apple\anonymous.json`（`filestore`）。
- 包装所有读接口，把 SDK 错误转成前端可用的 `{code, message, retryable}`。
- `resolvePlayback` 走设备池 + 重置重试（见 4.2）。
- 播放模型缓存：以 `episodeId` 为键，带 `expires_at`，过期或失败即重取。

### 6.2 本地媒体网关 `internal/gateway`

- 监听 `127.0.0.1`，端口 `0`（系统分配），启动时把端口回传前端。
- 每次播放生成随机 `token`（映射 URL/Key/清晰度/进度），URL 形如
  `http://127.0.0.1:<port>/media/<token>/index.m3u8`。
- 校验 `Host`/`Origin`，只允许 WebView2 来源，避免被本机其他程序当代理。
- 支持 `Range` 透传；HLS 分片短缓存。
- 管理 ffmpeg 子进程生命周期：切集/退出时 kill，退出时清理临时目录。
- 事件回传：转码/缓冲进度通过 Wails `runtime.EventsEmit` 通知前端。

### 6.3 手柄输入 `internal/input`

- Windows：XInput 轮询 goroutine，检测连接状态、按键、摇杆，做死区和重复率处理，归一为动作事件。
- 其他平台：stub（编译占位）。
- 通过 Wails 事件 `gamepad:action` 推给前端；前端也可查询当前连接状态。
- 键位映射表存在设置里，后端只发原始动作，映射可在前端做（推荐前端做，便于即时预览）。

### 6.4 存储 `internal/store`

- **SQLite**（`modernc.org/sqlite`，纯 Go 无 CGO，便于交叉编译）：
  - `history(series_id, episode_id, position, duration, finished, updated_at)`
  - `favorites(series_id, added_at)`
  - `search_history(keyword, updated_at)`
  - `series_cache(id, title, cover_url, payload, expires_at)`（可选）
- 设置项（含手柄映射）用 JSON 文件或 SQLite 单表。

### 6.5 Wails 绑定 API（`app.go`）

前端通过生成的 TS 绑定调用，主要方法：

```
// 浏览
Discover(opts) / Search(q, opts) / Suggest(prefix) / HotSearch() / SearchCues()
GetSeries(id) / ListEpisodes(id, opts) / Seasons(id) / SeriesRecommend(id) / GetAlbum(id)
ShortRank(query) / ShortFilterPanel(genre) / ShortFilter(query) / NewReleases(query)
Person(id) / PersonWorks(id, cursor)

// 播放
PreparePlayback(episodeId) -> PlayInfo{playUrl, qualities[], protected, duration, expiresAt}
SetQuality(token, quality)
ReportProgress(seriesId, episodeId, position, duration, finished)
GetResume(seriesId) -> {episodeId, position}

// 设备 / 设置 / 手柄
GetDevice() / ResetDevice() / GetSettings() / SaveSettings() / ClearCache()
GetGamepadState() / SetRumble(enabled)
```

`PlayInfo.playUrl` 指向本地网关，前端不接触上游 URL 和密钥。

## 7. 前端设计

### 7.1 页面

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 发现 | 频道切换、瀑布流卡片、无限滚动 |
| `/search` | 搜索 | 输入框、联想、热搜榜、结果 tab、屏幕键盘 |
| `/series/:id` | 详情 | 头部信息、分集网格、多季、相关推荐、演员 |
| `/play/:seriesId/:episodeId` | 播放器 | 自定义控件、清晰度、选集、自动下一集 |
| `/rank` | 榜单 | 内容/榜单切换、名次与升降 |
| `/category/:id` | 分类 | 筛选面板 + 列表 |
| `/person/:id` | 演员 | 主页 + 作品 |
| `/history` `/favorites` | 记录/收藏 | 续播入口 |
| `/settings` | 设置 | 设备、缓存、接口、手柄映射 |

### 7.2 播放器

- `hls.js` 挂到 `<video>`；清晰流 MP4 直接 `src`。
- 自定义控制条：播放/暂停、进度、音量、倍速、清晰度、上一集/下一集、全屏、网页全屏。
- 竖屏剧用 9:16 居中容器，横屏剧 16:9。
- 进度每 5s 及暂停/卸载时上报；进入播放页读取续播点（前 3s）。
- `ended` 事件触发下一集；下一集解析失败给出重试/跳过。
- 快捷键 + 手柄动作共用一套处理器。

### 7.3 状态与数据

- Zustand 管理播放器状态、当前剧集、设置、当前输入方式。
- 请求走 Wails 绑定；封面图直接 `<img>`（WebView2 自带磁盘缓存）。

### 7.4 输入抽象与焦点导航

- `src/input/`：动作定义、键鼠映射、手柄事件订阅、当前输入方式。
- `src/input/useAction.ts`：页面注册动作回调（如 `onConfirm`、`onBack`）。
- 空间导航统一在 `App` 层初始化，页面只负责给元素加 `focusable` 与 `focusKey`。
- 按键提示组件从"当前页 + 当前焦点"推导可用动作。

| 阶段 | 内容 | 验收 |
|---|---|---|
| **M0 脚手架** | Wails 工程、React/Vite/Tailwind、交叉编译出可运行 exe | Windows 11 能打开空窗口 |
| **M1 浏览** | 发现/搜索/详情/分集/榜单/演员，SQLite 记录 | 全流程只读可用 |
| **M2 清晰播放** | 本地网关反代 + hls.js，进度记忆、自动下一集 | 清晰分集可播、可拖动 |
| **M3 加密播放** | ffmpeg 解密转 HLS、清晰度切换、设备池、预取 | 加密分集可播 |
| **M4 手柄操作** | XInput 采集、动作层、空间导航、播放器控制、按键提示、屏幕键盘 | 纯手柄走通全流程 |
| **M5 打磨** | 收藏、分类筛选、设置、快捷键、错误提示、图标/安装包 | 可日常使用 |
| **M6 二期** | 缓存管理、DirectInput/RawInput 手柄兼容、更多细节 | 体验完善 |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 匿名设备"一次播放"限流 | 每集都要重置设备，体验差/失败 | 自动重置+退避重试、预取下一集；备选设备池 |
| 服务端接口改版 | SDK 失效 | 锁定 SDK 版本，关注其每日契约检查；接口地址可配置 |
| 加密方案变化 | ffmpeg 解不了 | 保留清晰流降级；跟进 SDK 的 DRM 实现 |
| ffmpeg 体积/合规 | 安装包大 | 首次运行按需下载 + 校验，或提供精简版 |
| 本地网关被滥用 | 安全 | 仅回环、随机 token、校验 Origin/Host |
| CDN 需要特定请求头 | 代理拉流失败 | 网关统一注入 User-Agent/Referer，失败切 BackupURL |
| 原生 XInput 只覆盖 Xbox 系 | PS/Switch 手柄不可用 | 文档引导 Steam Input/DS4Windows；后续加 DirectInput/RawInput |
| WebView2 Gamepad API 不稳定 | 兜底方案失效 | 以原生 XInput 为主 |
| 空间导航焦点错乱 | 手柄体验差 | 统一 focusKey、focus trap、返回恢复焦点，写焦点测试用例 |

## 11. 环境与构建

- 开发/构建机：Go 1.22+、Node 20+、Wails CLI、ffmpeg。
- 交叉编译（Linux → Windows）：
  ```sh
  wails build -platform windows/amd64 -nsis
  ```
- WebView2：Win11 预装；安装包内置 bootstrapper 兜底。
- 产物：`win-red-apple.exe`（+ 可选 `ffmpeg.exe`、NSIS 安装包）。
